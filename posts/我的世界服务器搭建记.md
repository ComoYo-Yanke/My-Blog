# 我的世界服务器搭建记

<a id="top"></a>

> 一台二手戴尔 3020M 小主机、一块 i3-4160T、8G 内存、120G 固态，加上 Ubuntu Server 和一堆脚本，变成了我和朋友们每天上线的地方。

## 硬件：捡垃圾捡出来的服务器

最近买了一台戴尔 OptiPlex 3020M（应该是这个型号，反正就是那种巴掌大的小主机），又配了点零件：

- **CPU**：i3-4160T —— 带 T 的低功耗版本，35W
- **内存**：金士顿 4G + 4G
- **硬盘**：120G 固态

全部装上去之后按下电源，居然真的点亮了，还能进 BIOS。说实话我是万万没想到的——二手配件拼起来能一次点亮，运气成分不小。

## 系统：Ubuntu Server

硬件没问题，就装了 Ubuntu Server。装系统这一步毫不夸张地说，全是我最擅长的环节，事情进展得比我自己预想的还要顺利。

没有桌面环境，开机就是一个黑框框，正合我意——省内存，也不用操心图形界面卡不卡。

## Minecraft：Fabric 服务端

系统装好，直接上了 Minecraft 的 Fabric 服务端。选 Fabric 是因为它轻、启动快，模组生态对服务端也比较友好。

公网开放这块没做端口映射，走的是内网穿透。家里没有公网 IP，穿透是最省事的方案：不用去动路由器，也不怕运营商哪天把公网 IP 收回去。

和朋友们玩下来体验还不错。

**想进来参观或者一起玩的话：**

```

```

加进多人游戏列表就能连。

## 自动化与运维

服务器跑起来只是开始，真正让人觉得舒服的是后面做的这些：

- **自动化脚本**：一键启动、停服前全体广播、定时备份存档
- **运维脚本**：日志轮转、磁盘占用检查、进程存活检测
- **监控网站**：CPU、内存、在线玩家、服务器状态，打开网页就能看

这些都弄好之后，日常基本不用管它。

## 最后

## English

> A second-hand Dell 3020M mini PC, an i3-4160T, 8 GB of RAM and a 120 GB SSD — plus Ubuntu Server and a pile of scripts — turned into the place my friends and I log into every day.

### Hardware: a server assembled from spare parts

I recently picked up a Dell OptiPlex 3020M (I believe that's the model — one of those palm-sized mini PCs) and gathered a few parts:

- **CPU**: i3-4160T — the low-power variant, 35 W
- **RAM**: two 4 GB Kingston sticks
- **Storage**: a 120 GB SSD

After putting it all together, I hit the power button — and it actually posted and got into the BIOS. Honestly, I did not expect that. Getting a machine to boot on the first try out of second-hand parts takes a fair bit of luck.

### The OS: Ubuntu Server

Since the hardware checked out, I installed Ubuntu Server. Installing the OS is squarely in my wheelhouse, and things went even more smoothly than I'd expected.

No desktop environment — just a black terminal on boot, which is exactly what I wanted: less memory used, and no worrying about whether a GUI would feel sluggish.

### Minecraft: a Fabric server

With the system up, the next step was a Minecraft Fabric server. I went with Fabric because it's lightweight, starts quickly, and its mod ecosystem behaves well on the server side.

For public access I skipped port forwarding and used a reverse tunnel instead (FRP). There's no public IP at home, so tunneling is the least hassle: no fiddling with the router, and no risk of the ISP quietly reclaiming the IP.

Playing with friends has worked out well so far.

**Want to drop by and have a look, or join in?**

```
frp-dry.com:20797
```

Just add it to your multiplayer list.

### Automation and operations

Getting the server running was only the beginning. What actually makes it pleasant is everything that came after:

- **Automation scripts**: one-command startup, a server-wide broadcast before shutdown, scheduled world backups
- **Ops scripts**: log rotation, disk usage checks, process liveness monitoring
- **A monitoring site**: CPU, memory, online players and server status, all visible in the browser

Once all of that was in place, day to day I basically don't have to touch it.

### Wrapping up

From digging up the hardware to having friends online, the whole thing went smoothly enough that it feels a little unreal. I used to think that "running a server for my friends" was a hassle. Actually doing it, every individual step was easy — the hard part was just starting.
